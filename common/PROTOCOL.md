# Протокол взаимодействия подсистем

Транспорт: Unix-сокеты `AF_UNIX / SOCK_STREAM`, путь `/run/fw/<subsystem>.sock`, права `0600`, владелец — пользователь подсистемы.
Формат: JSON, одно сообщение на строку (разделитель `\n`). Для `log.write.packet` — двоичный `packet_record_t` (55 байт).

## Конверт

```json
{"msg_id": 1042, "type": "request", "src": "cli", "dst": "authd", "cmd": "auth.login",
 "ts": "2026-03-14T10:21:33.482Z", "payload": {}, "reply_to": null}
```

Ответ: `type=response`, `reply_to=<msg_id запроса>`, `status=ok|error`, `error_code` (M01..M16), `error_message`, `payload`.
Событие: `type=event`, подтверждения не требует (`log.write.event`).

## Правила

- `src`: cli | web | filter | logd | authd | integrityd | os.
- Строки UTF-8, до 255 символов; время ISO 8601 с миллисекундами.
- Тайм-аут ответа 5 с; до 2 повторов с тем же `msg_id`; получатель по паре `(src, msg_id)` возвращает прежний ответ, команду повторно не выполняет.
- Счётчик `msg_id` в каждом процессе начинается со случайного значения (до 2^52): иначе два сеанса CLI или CLI и web с `msg_id=1` получили бы ответ друг друга.
- Нет ответа после повторов → M16 и неуспешное событие в журнале (FR-28).
- События при недоступной ПС-2 хранятся в очереди в памяти (до 1000), отправка повторяется каждые 5 с.

Реализация для Python: `common/fwcommon/protocol.py`.
