# ПС-4 WEB (fw-web)

- **Язык:** PHP (Debian 12) + nginx (HTTPS)
- **Пользователь ОС:** fw-web
- **Требования:** FR-03, FR-30 – FR-38, FR-44, FR-49
- **Команда:** Иванова, Мартыненко, Назмеева, Попов, Саитгареев (вместе с ПС-3)
- **Сокет:** `/run/fw/web.sock` (0600)

## Модули

| Модуль | Назначение |
|---|---|
| server | точка входа, маршрутизация, HTTPS на 8443 |
| auth | проверка сеанса, CSRF, роль в серверной сессии PHP |
| pages | разделы меню (таблица 7, столбец Web) |
| api | вызовы ядра управления / подсистем, проверка режима работы |

## Принимает

ПС-4 эквивалентна ПС-3 по интерфейсам (`src = "web"`): команд управления от других подсистем нет, входящие сообщения — только служебные уведомления.

| Команда | Назначение | Источник |
|---|---|---|
| `emergency.enter` | перейти в режим аварийной поддержки: доступны только разделы «Состояние», «Журналы», «Конфигурация» (просмотр) и «Система», остальные запросы отклоняются с M10 (FR-49) | ПС-6 |
| `emergency.exit` | вернуться в штатный режим | ПС-6 |
| `session.terminate` | принудительно завершить сеанс: показать M15 и сбросить сессию (FR-35) | ПС-5 |

Уведомления `emergency.*` приходят независимо от того, в каком интерфейсе (CLI или web) открыт сеанс администратора. ПС-6 отправляет их всегда и в ПС-3, и в ПС-4.

## Режим работы

Запросы к PHP обрабатываются независимыми процессами и состояния между ними не хранят, поэтому уведомление могло быть получено другим процессом или до его запуска. ПС-4 не полагается только на `emergency.*`:

- при каждом web-запросе запрашивает у ПС-6 `integrity.status` и применяет режим до выполнения действия;
- если ПС-6 не отвечает (M16), считает режим аварийным;
- повторные `emergency.enter` / `emergency.exit` идемпотентны: состояние не меняется, ответ успешный.

## Отправляет

Те же команды, что у ПС-3, с `src = "web"`:

- `auth.login`, `auth.logout`, `auth.ping`, `user.*`, `session.*` → ПС-5
- `rule.*`, `state.*`, `stats.get` → ПС-1
- `log.query.*`, `log.packets.clear` → ПС-2
- `integrity.*` → ПС-6 (`integrity.update_baseline` автоматически при `config save`)
- `config.*` → файлы, ПС-1, ПС-5, ПС-6
- `if.*`, `route.*`, `time.*`, `sys.*` → ОС (sudo, фиксированный список)

## Правила

- Шапка каждого файла по шаблону (см. `CONTRIBUTING.md`).
- Данные от администратора и из сети проверяются на входе; данным другой подсистемы без проверки не доверяют.
- Ошибки возвращаются кодом и сообщением из `common/messages.json`; необработанные исключения не завершают процесс.
- Правила проверки данных берутся из `common/validation.json` и должны давать те же результаты, что в ПС-3; общие тесты — в `tests/shared/`.
- Каждый модуль имеет unit-тесты; ПМИ своей подсистемы пишет её команда (`docs/pmi_template.md`).
