# ПС-6 Целостность (fw-integrityd)

- **Язык:** Python 3
- **Пользователь ОС:** fw-integrity
- **Требования:** FR-45 – FR-50
- **Команда:** Митяев, Цыбукова (вместе с ПС-5: Волнухина, Карцев)
- **Сокет:** `/run/fw/integrityd.sock` (0600)

## Модули

| Модуль | Назначение |
|---|---|
| hasher | SHA-256, HMAC-SHA-256 файла эталонов |
| checker | периодическая проверка, при запуске, по запросу |
| emergency | режим аварийной поддержки: блокировка трафика, уведомление ПС-3 и ПС-4, E40, M08 |
| restore | восстановление файлов из резервных копий с проверкой эталона |

## Принимает

| Команда | Назначение | Источник |
|---|---|---|
| `integrity.check` | принудительная проверка | ПС-3, ПС-4 |
| `integrity.status` | результат последней проверки и текущий режим (штатный / аварийный) | ПС-3, ПС-4 |
| `integrity.restore` | восстановить файл из резервной копии | ПС-3, ПС-4 |
| `integrity.update_baseline` | обновить эталон и резервную копию после штатного изменения | ПС-3, ПС-4 (автоматически при `config save`); ПС-5 (при `user add`, `user edit`, `user delete`) |

`integrity.status` — основной способ для ПС-3 и ПС-4 узнать режим: они запрашивают его при старте, входе и выполнении команд (ПС-4 — при каждом запросе).

## Отправляет

- `traffic.block` / `traffic.unblock` / `state.clear` → ПС-1
- `emergency.enter` / `emergency.exit` → ПС-3 **и** ПС-4 (для смены приглашения и запрета команд)
- `log.write.event` → ПС-2 (E40, E41, E42)

## Уведомление ПС-3 и ПС-4 о режиме

- Аварийный режим общесистемный: `emergency.enter` и `emergency.exit` уходят в обе подсистемы всегда, независимо от того, в каком интерфейсе открыт сеанс администратора (ПС-6 о сеансах не знает).
- Сообщения отправляются как запросы с ответом (`type=request`), а не как события. Получатели отправляются независимо: недоступность одного не задерживает другого.
- При отсутствии ответа: до двух повторов с тем же `msg_id`, затем неуспешное событие в журнал (FR-28) и повтор отправки, пока режим не подтверждён обоими получателями.
- Команды идемпотентны, поэтому повторная отправка безопасна.
- Порядок при нарушении целостности: `traffic.block` и `state.clear` → ПС-1, `emergency.enter` → ПС-3 и ПС-4, E40, M08.
- Порядок при успешном восстановлении: повторная проверка, `traffic.unblock` → ПС-1, `emergency.exit` → ПС-3 и ПС-4, E41.

## Запуск

`fw-integrityd` стартует до `fw-filter`. ПС-1 стартует в режиме `emergency_mode=1` (drop-all); обработка трафика включается только после успешной проверки целостности командой `traffic.unblock` (FR-04, FR-48).

## Правила

- Шапка каждого файла по шаблону (см. `CONTRIBUTING.md`).
- Данные от администратора и из сети проверяются на входе; данным другой подсистемы без проверки не доверяют.
- Ошибки возвращаются кодом и сообщением из `common/messages.json`; необработанные исключения не завершают процесс.
- Каждый модуль имеет unit-тесты; ПМИ своей подсистемы пишет её команда (`docs/pmi_template.md`).
