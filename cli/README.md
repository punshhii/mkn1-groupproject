# ПС-3 CLI (fw-cli)

- **Язык:** Python 3
- **Пользователь ОС:** fw-cli
- **Требования:** FR-02, FR-30 – FR-38, FR-44, FR-49
- **Команда:** Иванова, Мартыненко, Назмеева, Попов, Саитгареев (вместе с ПС-4)
- **Сокет:** `/run/fw/cli.sock` (0600)

## Модули

| Модуль | Назначение |
|---|---|
| repl | цикл чтения-выполнения, приглашения `admin@fw[rw]>`, `admin@fw[ro]>`, `admin@fw[EMERGENCY]>` |
| parser | разбор команд «группа действие [аргументы]» |
| formatter | вывод таблиц и страниц |
| session | локальный кэш роли, `auth.ping`, режим работы (штатный / аварийный) |

## Принимает

ПС-3 — клиент: команд управления от других подсистем нет. Входящие сообщения — только служебные уведомления о режиме и сеансе.

| Команда | Назначение | Источник |
|---|---|---|
| `emergency.enter` | перейти в режим аварийной поддержки: приглашение `[EMERGENCY]`, команды вне столбца «Авар.» таблицы 7 отклоняются с M10 (FR-49) | ПС-6 |
| `emergency.exit` | вернуться в штатный режим: приглашение `[rw]` или `[ro]` по роли сеанса | ПС-6 |
| `session.terminate` | принудительно завершить сеанс: вывести M15 и завершить работу (FR-35) | ПС-5 |

Уведомления `emergency.*` приходят независимо от того, в каком интерфейсе (CLI или web) открыт сеанс администратора. ПС-6 отправляет их всегда и в ПС-3, и в ПС-4.

## Режим работы

Процесс CLI запускается отдельно для каждого входа (консоль, SSH с ForceCommand) и может не получить уведомление, отправленное до его запуска. Поэтому, помимо `emergency.*`, ПС-3 сама узнаёт режим:

- при старте, после входа и перед выполнением каждой команды запрашивает у ПС-6 `integrity.status`;
- если ПС-6 не отвечает (M16), считает режим аварийным;
- повторные `emergency.enter` / `emergency.exit` идемпотентны: состояние не меняется, ответ успешный.

## Отправляет

- `auth.login`, `auth.logout`, `auth.ping`, `user.*`, `session.*` → ПС-5
- `rule.*`, `state.*`, `stats.get` → ПС-1
- `log.query.*`, `log.packets.clear`, `log.flush` (при shutdown) → ПС-2
- `integrity.*` → ПС-6 (`integrity.update_baseline` автоматически при `config save`)
- `config.*` → файлы (self), ПС-1, ПС-5, ПС-6
- `if.*`, `route.*`, `time.*`, `sys.*` → ОС (sudo, фиксированный список)

## Правила

- Шапка каждого файла по шаблону (см. `CONTRIBUTING.md`).
- Данные от администратора и из сети проверяются на входе; данным другой подсистемы без проверки не доверяют.
- Ошибки возвращаются кодом и сообщением из `common/messages.json`; необработанные исключения не завершают процесс.
- Правила проверки данных берутся из `common/validation.json`; общие тесты с ПС-4 — в `tests/shared/`.
- Каждый модуль имеет unit-тесты; ПМИ своей подсистемы пишет её команда (`docs/pmi_template.md`).
